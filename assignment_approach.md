# Assignment Approach: Word Puzzle Game Plus

Here is a breakdown of how you can approach the assignment, with a suggested workflow for your team of three.

### Role-Based Task Distribution

**1. Test Manager:**

*   **Primary Deliverable:** The `Group_Test_Management_Report.md` file.
*   **Tasks:**
    *   Create the initial report file.
    *   Draft the **Test Plan** section (objectives, scope, schedule, etc.).
    *   Coordinate with the team to ensure all sections of the report are completed.
    *   Track and fill in the **Test Monitoring & Metrics** section.
    *   Oversee the final submission.

**2. Risk Analyst:**

*   **Primary Deliverable:** The **Risk Analysis** section of the report.
*   **Tasks:**
    *   Identify at least 6 risks related to the new features (Reset Game, Leaderboard, Bonus Round).
    *   Prioritize these risks using a Likelihood/Impact matrix.
    *   Define mitigation strategies for each risk.
    *   Design at least 5 **risk-based test cases**.
    *   Create a risk-coverage pie chart for the report.

**3. Test Executor:**

*   **Primary Deliverable:** The **Test Design & Execution** and **Defect Reporting** sections.
*   **Tasks:**
    *   Execute all 8 test cases (5 risk-based, 2 negative, 1 usability).
    *   Record the test results in the report.
    *   Log at least 3 defects as GitHub Issues, with all the required details (steps to reproduce, severity, etc.).
    *   Link the GitHub issues to the report.
    *   Capture screenshots or other evidence for your test results and defects.

### Suggested Workflow

1.  **Team Kick-off:**
    *   Have a meeting to ensure everyone understands their roles and the assignment requirements.
    *   The **Test Manager** should create the `Group_Test_Management_Report.md` file and set up a project in GitHub to manage tasks and issues.

2.  **Phase 1: Planning & Analysis (Days 1-2)**
    *   **Test Manager:** Drafts the initial Test Plan.
    *   **Risk Analyst:** Identifies and analyzes risks, then shares them with the team for feedback.

3.  **Phase 2: Test Design (Day 3)**
    *   **Risk Analyst:** Designs the 5 risk-based test cases based on the identified risks.
    *   **All Members:** Collaborate to create the remaining 3 test cases (2 negative, 1 usability).

4.  **Phase 3: Execution & Reporting (Days 4-5)**
    *   **Test Executor:** Executes all test cases using the `index.html` file and records the results. Any bugs found are logged as GitHub Issues.
    *   **All Members:** Start filling in their respective sections of the report.

5.  **Phase 4: Finalization & Submission (Day 6)**
    *   **All Members:** Write the **Reflection** section together.
    *   **Test Manager:** Reviews the entire report, ensures all metrics are calculated and everything is complete, and then submits the final `Group_Test_Management_Report.md`.
